\mdsec{The question}
Endgame tables store the exact value of every position, and they are large. Can we keep only part of a table,
still answer every exact query from it, and certify that the answers are right?
\mdgap
\mdsec{How we are approaching it}
\begin{itemize}
\item Store signed distance intervals on part of the game graph.
\item Recover the rest from two extremal boundary problems, without widening any interval.
\item Certify every stored interval at both of its endpoints.
\item Place checkpoints in a periodic pattern, which bounds how deep a lookup has to search.
\end{itemize}

\mdsec{What we have so far}
\begin{progress}
We have a sound and complete certificate for any stored subset of a finite alternating game with irreversible budget resets. It works even when the omitted part contains cycles.
\end{progress}
\begin{progress}
Certification takes $O\bigl((w + \log(N+2))(N+E)\bigr)$ graph operations for intervals of width at most $w$, and $O(w(N+E))$ when the omitted part is acyclic.
\end{progress}
\begin{progress}
The 26 classes fit in 7,585,632 bytes with all five outcome categories and exact values kept, and every file passes certification.
\end{progress}
\end{mdcol}

\mdsec{Open questions}
\begin{itemize}
\item Near the threshold, lookups still take 133 ms at the 99th percentile, despite the seven-ply depth bound. How can that come down?
\item The savings come from the chess implementation; the general checker and grid optimizer were tested separately. What does the general method save on other games?
\end{itemize}
